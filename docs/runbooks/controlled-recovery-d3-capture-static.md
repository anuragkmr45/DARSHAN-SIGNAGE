# D3 capture tools — static review boundary

This packet supplies fixed adapters for the existing brokered backup orchestrator. It authorizes no live command. `loadInstalledD3Capture()` always rejects with `CONTROLLED_RECOVERY_D3_CAPTURE_NOT_ADMITTED`; no capture CLI is registered. Source/data/capsule/reservation/broker profile identities are unchanged. Live seed remains separately enrolled; capsule, reservation, broker, capture, D2 and whole-run gates remain false.

The capture profile is `deploy/development/controlled-recovery/tiny-d3.capture-profile.json`. Its pg_dump, tar and age executable attestations are deliberately null. The planned `/bin/tar` argv requires GNU deterministic USTAR features which have **not** been proven in the enrolled Alpine PostgreSQL image. Byte fixtures prove the archive validator and unchanged production extractor, not that image capability. A separately reviewed image capability/fingerprint packet must resolve this blocker before any installed capture admission. No image was built, pulled, replaced or newly enrolled here.

`ProtectedD3CapturePrerequisites` reuses the accepted seed/seal, capsule, reservation and broker readers and requires an exact READY broker receipt. It binds their real identities to the capture attempt; missing live receipts are not synthesized. The adapters match the production `runBrokeredEncryptedBackup` dependency signatures without starting that orchestrator or any app/job. The unused earlier reservation custom-dump argv is not invoked: the new capture adapter uses the production restore contract's producer-named plain SQL dump and excludes `darshan_d3_control`.

The spool holds an exclusive operation owner through all tracked producers, including ignored promises. Attempt duration is at most five minutes; files are at most8MiB, total producer bytes32MiB, objects128, pages16 per allowed source, serial concurrency1. Fixed tool containers are read-only, numeric enrolled UID:GID, drop all capabilities,128MiB/32 PIDs/0.25 CPU. They override the inherited PostgreSQL data volume with a1MiB tmpfs and remove only exact verified IDs with `--volumes`. No source container ID is an input. An uncertain process/container/credential/content cleanup retains the owner and quarantine marker; it never performs stale-owner takeover or recursive cleanup. Restart status is a read-only index, not verification authority. Retained ambiguous state requires separate review.

Cancellation settlement now requires a branded producer with immutable identity, an observed `closed` proof and `terminateAndJoin`. A raw iterable is refused before plaintext creation. On abort, deadline or failure, the exact process/socket upstream is terminated and joined **before** iterator return/next and disk tails are joined. This includes path/open/iterator initialization failure; an abort hook can stop upstream while output initialization remains pending. The writer combines the operation and component cancellation signals. Fixed bounds are3500ms upstream,1000ms iterator/write/close,3500ms attached-output consumer and10000ms controller drain per pass. Opaque callbacks and ignored producer promises are included in the bounded drain; a normal-drain timeout can require a second bounded cancellation drain. The attempt timer stays armed while a producer is pending. These settlement bounds do not change admission/resource/process limits or profile identities.

Only proven producer closure, iterator/sink closure and callback settlement permit exact plaintext cleanup and owner release. Unjoined CLI/output, stalled next/return/write/close, uncertain client closure or callback drain retain owner, plaintext/spool/CID evidence and an enum-only quarantine receipt. Late callbacks cannot unlink credentials or verification plaintext after quarantine. First failure remains latched across caught/ignored nested failures; its internal non-enumerable cause is retained, while error messages, public JSON and quarantine classifications contain no raw diagnostics or secrets. Abort is rechecked after admission and before queued effects; completed create IDs may still be recorded under the retained owner, without starting a container. HTTP bounded projections join the original readable before their projection closes, and abort promptly destroys the S3 client. This correction authorizes no live operation.

PostgreSQL capture uses fixed `/usr/local/bin/pg_dump`, source network/database/user, certificate verification, CA and0600 PGPASSFILE read-only binds. Passwords are absent from argv/environment/diagnostics. Stdout streams with backpressure to an exclusive0600 producer file; stderr is bounded and discarded. Object capture exposes only authenticated TLS List/Head/Get, uses the canonical backup bucket/prefix allowlist (including archive logs), verifies the accepted sealed inventory, If-Match/version/length/SHA and a second listing. Unknown paths, pagination loops, duplicates, changes and unsettled bodies fail closed. Tar verification checks exact sorted file-only USTAR entries, mode0600,uid/gid0,mtime0, checksums/content/padding and then invokes the unchanged production extractor and dump contract.

The age fingerprint seam returns actual `/usr/bin/age` executable SHA and version. A fixed network-free `/usr/bin/sha256sum /usr/bin/age` read-only container operation is the sole direct utility entrypoint; output-producing age/ffmpeg operations retain the compiled umask077 wrapper. No fingerprint was executed or invented here. Configuration keeps the existing durable age transaction; database and objects receive distinct immutable full-attempt/binding scopes while sharing the same exclusive staging slot. Private age identity remains outside capsule/spool plaintext. The actual container executable identity is manifest metadata for the overridden adapter; no host `AGE_PATH` or ordinary worker activation is claimed.
