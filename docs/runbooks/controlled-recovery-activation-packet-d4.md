# Controlled Recovery Activation Packet D4 — Containerized Tools Authority

The [static capsule packet](controlled-recovery-d3-capsule-static.md) introduces a reusable transaction using the same durable age slot as ordinary fixed D4 operations. It owns plaintext staging before publication through joined roundtrip verification, durable ciphertext receipt and exact cleanup. Uncertain owners/processes remain locked; only proven settled exact publication windows can recover. Tool argv/image/config/private age identity are unchanged. This static packet does not run encryption or admit live capsule/capture.

Subpacket 2A corrects the inherited PostgreSQL VOLUME: fixed tool argv now overrides `/var/lib/postgresql/data` with a 1 MiB 0700 tmpfs owned by the enrolled developer UID:GID; exact container removal includes `--volumes`. The image/config identity and retained age key/receipts are unchanged. Existing unattributed anonymous volumes were not removed. See [the source runtime boundary](controlled-recovery-d3-source-subpacket2a.md).

Packet D4 replaces host `age`, `age-keygen`, `ffmpeg` and `ffprobe` prerequisites with one fixed development-only Docker image. It does not activate D3 or authorize a recovery run. The initial implementation was static; separately authorized root-agent builds and the bounded crypto check are recorded below. No host package installation is needed.

The bounded live age check subsequently found a real output-mode defect: the original image created encrypted output as 0644. Protected output validation rejected it and the exact container was cleaned up. The correction uses `darshan-d3-tool.c`: a small statically compiled wrapper that sets `umask(0077)` before `execv`, accepts only the four exact absolute age/codec tool paths, and uses no shell or PATH lookup. Every typed runtime command uses this wrapper as entrypoint with the enrolled tool path as its first argument. There is no chmod-after-output workaround. The retained key, legacy public receipt and failed ciphertext remain preserved for the operator's later bounded verification.

The corrected image was built by root under a 512 MiB cap and its observed identity is enrolled. The wrapper binary SHA is `b860f34f61b12a820a6f3dd78c5df711fbedf3e209735750b1873a73eaa446b9`. The build pins temporary `build-base=0.5-r4`, compiles statically, removes the virtual build dependency, and checks that neither `/usr/bin/cc` nor `/usr/bin/gcc` is executable. Broken compiler symlinks do not count as installed compilers. It verifies source hash, wrapper 0555 mode, recorded binary SHA-256, an actual 0600-creation self-test, rejection of an unapproved executable, and all four approved tools. Only wrapper/hash files are copied to the final stage, where hash/mode/self-test/tool-version checks repeat. Root also passed the subsequent exact-binary-hash rebuild; final image ID/config/repository digest were unchanged and inspection reports `wrapperBinaryVerificationPending:false`. The bounded crypto roundtrip remains a separate check.

The build context is fixed at `/home/hexmon/Desktop/DARSHAN-SIGNAGE/deploy/development/controlled-recovery/tools`. The Dockerfile uses the already enrolled immutable `postgres:16-alpine` digest as its Alpine base, accepts only exact reviewed APK versions for `age` and `ffmpeg`, and contains no curl/download script. The corrected canonical lock enrolls age `1.3.2-r1`, ffmpeg `8.1.3-r0`, image ID/digest `sha256:22c34e187a9650e0bc319e95cfcbd12e770a2643df898c12880d9be96a6b35a3` and config hash `c2741ddea226184879e850990e1717128d9b7cf5bf003703d89cdd082a7fa7a8`. D3 identity verification is enabled; the missing installed low-level boundary factory still blocks whole-run effects.

At runtime `D3ContainerToolRunner` permits only typed age version/keygen/recipient/encrypt/decrypt and fixed ffmpeg/ffprobe operations. Every container uses the exact enrolled image ID, `--pull never`, `--network none`, read-only root, all capabilities dropped, no-new-privileges, the exact enrolled developer UID:GID, fixed PID/memory/CPU caps, bounded tmpfs/output/time and exact D3-root bind mounts. The private age identity is mounted read-only for decrypt and `age-keygen -y`. Recipient validation uses the existing Bech32/X25519 validator. No host age is trusted.

`DirectD3ToolExecution` directly spawns only `/usr/bin/docker`, reconstructs and compares the complete fixed command, disables shell/stdin, and supplies a fixed environment without ambient credentials. Before dispatch it rechecks the protected empty Docker configuration, enrolled socket/context/daemon and image/config/labels. Container names, ownership labels and protected cidfiles bind operation plus component. Same-name resources are refused before launch; cleanup requires the exact CID, name, image and labels. CLI processes and exact containers are settled on normal completion, nonzero exit, output overflow, timeout and abort. Ambiguous cleanup or an unjoined CLI retains the protected slot lock and fails closed. Do not delete a retained lock/cidfile without investigating its exact container and process ownership.

Shared age/media staging slots serialize in-process and use exclusive protected directory locks across processes. All owned directories and inputs/outputs must meet 0700/0600 ownership/link/device/bounds checks; broad permissions are never granted. Existing output paths are refused, and a tool output with an unsafe mode fails verification. There is no generic argv, endpoint, image, mount or operator path surface. An already aborted operation dispatches nothing.

The D3 backend environment intentionally carries no host `AGE_PATH`, `AGE_VERSION` or `AGE_SHA256` claim. Packet D4 backup/recovery/media effects are controller-owned and use the typed container boundary. The ordinary server worker's production backup implementation is unchanged. D2 and the whole-run boundary remain closed until the complete stage dependencies are enrolled; D3 `enabled:true` permits identity verification only.

```bash
cd /home/hexmon/Desktop/DARSHAN-SIGNAGE/darshan-server
npm run controlled-recovery:d4-tools:build
```

The command reads the fixed lock, verifies the Dockerfile hash, uses the immutable base and fixed context/tag, passes only the two locked package versions, and bounds time/output. After the authorized build, obtain the secret-free identity receipt with:

```bash

npm run controlled-recovery:d4-tools:inspect > /home/hexmon/Desktop/DARSHAN-SIGNAGE/.controlled-recovery-d3/evidence/d4-tools-image-inspection.json
```
