# Air-Gapped First Release Boundary

The first release uses local email/password sign-in and recovery. SSO UI and server routes are absent; old SSO routes return 404. The authoritative source-free Backend `start.sh` and upgrade path run `npm run production:preflight:sso` from the compiled backend CLI before activating API or worker containers. It prints counts only and blocks active SSO configurations or stored client secrets. An administrator must deliberately scrub legacy secrets before release; no migration silently removes them. The command may also be run manually as a read-only diagnostic. API-key management and the explicit webhook Test action remain separate features, with no automatic business-event delivery claim.

If the preflight blocks an upgrade, leave the current release running, record an approved change ticket and take the required backup. A database administrator may then deliberately deactivate the retained configurations and replace their secrets with the empty non-secret value required by the legacy non-null column: `UPDATE sso_configs SET is_active = false, client_secret = '' WHERE is_active OR length(client_secret) > 0;`. Run the statement in an explicit transaction over the verified TLS database path, record affected-row counts only, and rerun the preflight before deployment. Never print or copy the prior secret values into evidence.

Verify HTTPS and certificate identity for every cross-VM and user/player DARSHAN path, including WebSocket and media delivery. HTTP is allowed only for private hops within a same-VM Docker network. The generated source-free topology supplies verified TLS. The direct Compose CMS publishes HTTP and therefore needs a site TLS ingress before it can satisfy the user-facing boundary; do not approve it on its own.

Webpage playback/capture and explicit webhook Test may contact **approved private HTTP or HTTPS** destinations. Configure approved hosts, ports and private CIDRs together. Public addresses, loopback, link-local, metadata endpoints, URL credentials, unapproved redirects and unresolved hosts are denied. Webhook Test pins each validated DNS address for the connection, enforces same-origin redirects, a five-second total timeout and 64 KiB response limit, and sends only a synthetic `webhook.test` event. Browser capture and Electron webviews can re-resolve DNS after their preflight checks; a site egress firewall blocking public and unapproved private destinations is therefore required to enforce the boundary at connection time. Record approved DNS and IP ranges; do not use broad public proxy trust. `TRUSTED_PROXY_CIDRS` should contain only the actual reverse-proxy source addresses so `x-forwarded-for` cannot be forged by direct clients while rate limiting sees distinct players behind the proxy.

Release QA must prove local login/recovery, SSO 404, approved private HTTP and HTTPS, denied public/metadata/loopback/unapproved private addresses, redirect and DNS rebinding behavior, and cross-VM certificate failures. Source checks alone do not verify the site's network or firewall.
