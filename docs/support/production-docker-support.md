# Production Docker Support

Last code-truth refresh: 2026-06-28.

## Production Model

Production uses Docker role deployments on Ubuntu Server VMs. Proxmox is the hypervisor only.

| Role | Source |
|---|---|
| Data | `deploy/production/docker/data/docker-compose.yml`, `start-data.sh` |
| Valkey | `deploy/production/docker/valkey/docker-compose.yml`, `start-valkey.sh` |
| Backend | `deploy/production/docker/backend/docker-compose.yml`, `start-backend.sh` |
| CMS | `deploy/production/docker/cms/docker-compose.yml`, CMS nginx files |
| Observability | `deploy/production/docker/observability/docker-compose.yml` |

Use `deploy/production/README.md` for full setup commands.

## Support Order

1. Data VM.
2. Valkey VM.
3. Backend VM.
4. CMS VM.
5. Observability VM.
6. Player devices.

The backend cannot become healthy if DB/object storage or required schema are missing. CMS can start but will not be useful if backend is unavailable.

## Data VM

Check:

- Postgres container is running.
- MinIO container is running.
- published ports match `deploy/production/docker/.env`.
- data volumes exist and were not accidentally recreated.

Do not run destructive reset scripts unless the operator explicitly requested a fresh start.

## Valkey VM

Check:

- Valkey container is running.
- backend `VALKEY_URL` points at the Valkey VM/port.
- backend logs do not show Valkey DNS/connectivity failures.

Realtime is notification-only; REST/DB and polling remain authoritative fallback.

## Backend VM

Check:

- `darshan-server/.env` exists and contains secrets/sensitive URLs.
- `darshan-server/config/backend.json` exists and is mounted as `/app/config/backend.json`.
- `DARSHAN_CONFIG_FILE=/app/config/backend.json` inside Docker.
- backend cert files exist or were generated by the production helper.
- runtime tools are available: ffmpeg, LibreOffice, `pg_dump`, `tar`, Playwright Chromium if enabled.
- DB schema/bootstrap has been run when starting from an empty DB.

If backend starts then exits with `relation ... does not exist`, the schema was not pushed/migrated for that database.

## CMS VM

Check:

- `darshan-cms/public/config/app-config.json` exists.
- CMS nginx serves `/config/app-config.json` with browser-visible, non-secret values.
- nginx proxies `/api/v1`, `/socket.io`, and `/grafana` according to deployment config.
- nested route refresh returns the CMS app, not a 404.

Do not put secrets in `darshan-cms/.env` or runtime config.

## Observability VM

Check:

- Prometheus is healthy.
- Grafana is reachable at the configured root URL/path.
- Prometheus targets match the actual VM IPs/ports.
- Rules and dashboards from `deploy/shared/observability/*` are loaded.

Scrape and alert correctness is `needs runtime verification`.

## Player Connectivity

Player machines are not Docker server roles. They need the packaged player, player site config, and network access to backend/CMS/media endpoints.

Expected player site config path:

```bash
/etc/darshan/player/config.json
```

## Do Not Claim Production Ready

Healthy containers are necessary but not sufficient. Browser QA, packaged player QA, media rendering, screenshots, PoP, realtime latency/fallback, and no-secret review remain separate evidence gates.
