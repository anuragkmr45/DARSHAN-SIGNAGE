# Performance, Load And Resilience Plan

This document primarily designs future tests. A short targeted Linux Electron characterization was executed on 2026-10-15: two simultaneous loop videos ran for 12 seconds, a mixed video/PDF sequence cycled, a corrupt video recovered to PDF page 19, cached looping survived an offline restart, and a schedule stopped approximately 105 ms after its boundary. Requirements 19–24 now have focused fake-clock/fault automation plus two current Linux Electron runs recorded in `evidence/playback-recovery-developer-verification-2026-10-21.md`. Neither record is a soak/capacity pass. Run the remaining plan only on isolated hardware and data that represent the five VM roles and actual player models. Obtain BQ-017 workload/SLO inputs, BQ-018 RPO/RTO and BQ-019 network boundary before assigning release pass/fail limits. The sample 500-player capacity template is not an approved target.

## Recovery Measures

For backup/restore and role update, record start/end timestamps, schedule identity, queue job ID, attempt ID/number, stage, lease/deadline/retry/cancellation transitions, last durable transaction, object counts/hashes, manifest key ID, independent-copy receipt, last displayed schedule, accepted versus persisted PoP and queue backlog. Calculate observed data loss and recovery time from these records. The confirmed RTO target is four hours and planned maintenance downtime is at most two hours; RPO, exact daily time/timezone and failure-domain promise remain BQ-018/027. Preserve the distinction between Packet 1 coordination, Packet 2 consistent capture, Packet 3 encryption/publication primitives, future retention/restore/promotion, application rollback and database/object restore; the migration code has no automatic reverse schema path.

The following remain mandatory QA/release work on an isolated larger machine and must not
be inferred from the low-resource developer run: load/stress/soak; multiple simultaneous
players or browsers; two-node realtime/Valkey; full API+worker+observability production
topology; Windows and physical-display behavior; long video/PDF memory-growth; and
production backup/restore plus deployment rehearsal.
