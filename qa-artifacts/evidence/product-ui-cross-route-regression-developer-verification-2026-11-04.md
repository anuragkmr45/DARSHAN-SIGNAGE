# Cross-route CMS redesign regression: developer verification

Branch: `codex/darshan-product-ui-redesign-20261103`. This is fixture-backed developer evidence, not human QA or production acceptance.

## Findings and correction

- The first broad Playwright run stopped after four failures. Three dark-phone cases still set the obsolete `theme` browser-storage key, although public and authenticated appearance now come from site settings. A Users case expected the retired `Users Management` heading. All nine affected dark-mode specs now install saved dark site responses; the Users assertion uses the current heading.
- Private appearance and branding responses were trusted at runtime. An empty or malformed response could set an invalid accent or replace a valid public brand. `AppSettingsBootstrap` now accepts only known theme, accent and sidebar values, a nonblank app name, and a null or safe image URL. A browser fixture verifies malformed private responses preserve the public site title, favicon and Forest accent.
- A Schedule Queue test selected a publish-failure message in both the visible toast and its accessibility status. The assertion now targets the toast; no publish behavior changed.

## Checks

- Focused browser rerun of the initial four failures plus the malformed-settings case: **5/5 passed**.
- Final CMS production build and bundle budget: **passed**. Unit suite: **283/283 passed**. Focused ESLint: **passed**.
- Broad Chromium browser run, one worker: **176 passed, 5 skipped, 1 failed** in 13.2 minutes. The sole failure was the duplicate-text assertion above. The five skipped cases require optional live chat credentials or preconditions.
- After the assertion and final branding-URL guard, focused browser rerun: **2/2 passed** (publish failure recovery and malformed-branding fallback). The broad suite was not repeated after these narrow changes. `git diff --check` passed.
- Browser screenshots generated by the broad run were retained as current fixture captures; inspected dark phone API Keys and phone Live Broadcasts views. They contain test data, not production data.

## Still open

Exercise the saved public appearance and private Settings responses together against a matched deployed server; check customer branding URLs, all route/control states, keyboard and screen-reader behavior, text zoom, packaged Ubuntu/Windows player, physical display and independent human QA. The browser suite cannot establish those outcomes.
