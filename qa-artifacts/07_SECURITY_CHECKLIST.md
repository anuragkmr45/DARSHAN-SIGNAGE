# Security Verification Plan

Planning only. Perform the following checks only in an approved isolated environment with nonproduction accounts, objects and keys. Map findings to `03_RISK_REGISTER.csv` and case IDs in `05_TEST_CASES.csv`. OWASP ASVS/WSTG categories are organizing references, not a claim of certification.

| Control area | Human verification | Case IDs / evidence |
| --- | --- | --- |
| Identity and sessions | Test wrong/inactive/deleted credentials, throttle failures, invite/reset/activation token replay, session expiry, logout and immediate withdrawal from REST and already-connected sockets. During tombstone, transfer, disablement, role change and password reset verify all target JTIs disappear, user rooms disconnect and reconnect is rejected; during deletion also prove no new recipient notification commits. Test permission-definition and recovery-CLI changes separately. | `AUTHN-01..04`, `CONC-07`; `darshan-server/src/auth/jwt.ts`, user/notification repositories, user routes and realtime namespaces |
| Role administration | Test every SUPER_ADMIN user target; block deletion of every SUPER_ADMIN; block edits/rename of built-in roles; ensure custom-role grant and assignment paths cannot exceed intended scope. | `AUTHZ-01..02`; `darshan-server/src/rbac/policy.ts`, `src/routes/roles.ts` |
| Horizontal authorization and ownership | Use organization, two departments and restricted rows with creator, peer, DEPARTMENT lead, moved/deleted creator, custom role and administrators for Media/Layout/Presentation/Schedule. Call list/detail/mutation/item/slot/request APIs directly using guessed IDs; inspect pagination/count and expanded nested data. Test ability denial independently from ownership denial and attempt scope-incompatible parent/child references. The former Presentation omission is source-fixed but not runtime-proven. | `AUTHZ-04..05`, `AUTHZ-07`, `SEC-01`; `darshan-server/src/rbac/content-ownership.ts`, content routes, `evidence/deleted-user-ownership-review.md` |
| Tombstone privacy and integrity | Confirm normal directories/search/invites omit deleted users; history exposes retained name/status but never the original email/password/invite token; original email is reusable; second delete is idempotent; update/reactivate/login/reset/activation fail. Confirm creator/owner columns and historical Schedule Request/audit/chat references are unchanged. | `DATA-06`, `UI-07`; migration `0045`, user repository/routes, audit/request projections |
| Delegated emergency | Test screen manager entry in CMS, direct API trigger/clear, selected/unselected screen IDs, group/all scope and clear by another delegate. Only selected-screen delegation is confirmed; additional scope is BQ-003. | `AUTHZ-03`, `FUN-07`; `darshan-server/src/routes/emergency.ts` |
| Excluded workboard exposure | Keep `/requests` out of functional/UAT acceptance while checking authentication, read scope and mutation exposure if routes remain reachable. | `AUTHZ-06`, `SEC-01`; `darshan-server/src/routes/requests.ts` |
| Browser session and CSRF | Inspect same-site cookies, credentialed requests, origin/CSRF checks, direct URL access, stale tabs and error responses. Verify that hiding a CMS control does not stand in for a backend denial. | `AUTHN-02`, `UI-02`, `SEC-01`; `darshan-cms/src/api/apiClient.ts`, `darshan-server/src/server/index.ts` |
| Inputs and output encoding | Use benign malformed inputs for IDs, Unicode, template text, markdown/chat messages and exported PDF/CSV; confirm validation and encoded rendering. Check database writes and logs for accidental partial or secret data. | `API-01`, `FUN-09`, `FUN-11`; server schemas/routes and `src/utils/pdf-render.ts` |
| Document page selection | Reject API over-posting, zero/negative/fractional/overflow pages, page values on non-documents, invalid layout slots and non-READY media before replacement. Recheck the known cross-owner presentation mutation surface with the new bulk PUT. Confirm signed PDF access remains authorized/short-lived, PDFs are parsed without script evaluation, encrypted/malformed files fail closed, and errors/logs expose neither source bytes nor signed URLs. | `FILE-06`, `API-05`, `API-06`, `AUTHZ-05`, `SEC-01`; `darshan-server/src/utils/pdf-metadata.ts`, `document-page-selection.ts`, `routes/presentations.ts` |
| Video-loop interruption and teardown | Over-post loop on non-video media and verify normalization. Interrupt a loop during load, seek, play retry, stall, fade and normal playback using schedule end, snapshot replacement, emergency/default takeover and secure lock. Confirm every hidden video is paused, detached and stripped of its source; no hidden audio, stale callback, repeated error storm, signed media URL or credential remains. | `API-07`, `PLAYER-11`, `PLAYER-12`, `OBS-04`; `darshan-player/src/renderer/scheduled-video-lifecycle.ts`, `player-layout-helpers.ts`, `player.ts` |
| Uploads and object access | Check MIME, size, SHA-256, multipart ownership, signed URL expiry, wrong/deleted user/session, object-key traversal and private download access. Race deletion against INITIALIZING/ACTIVE/FINALIZING and legacy PENDING uploads in both commit orders; inject abort/delete failure and prove no incomplete object becomes READY while cleanup retries safely. | `FILE-01..05`, `CONC-02`, `CONC-07`; media/user/upload repositories, `darshan-server/src/routes/media.ts`, `src/jobs/index.ts`, `src/s3/index.ts` |
| Webpage SSRF boundary | Test URL scheme, username/password, host/resource allowlists, redirects, DNS rebinding fixture, private CIDR and hard-denied loopback/link-local; invalid certificate must remain rejected. Do not use a real internal target. | `FUN-08`, `PLAYER-09`; `darshan-server/src/utils/webpage-url-policy.ts`, player network policy |
| Device identity and replay | Test certificate/site mismatch, revoked identity, timestamp/nonce replay, signed REST versus socket handshake, and resumption after network failure. TLS transport trust and signed request authorization are separate checks. | `API-02`, `PLAYER-01`; server device auth and player cert manager |
| Secrets and release trust | Verify target host has independently pinned public key, signed manifest covers installer and role, unsafe archives reject before activation, runtime secrets stay outside browser bundle/logs and are readable only by intended process. | `DEP-01`, `SEC-02`; `scripts/bundle/install-signed-role.sh`, role lifecycle |
| Network and monitoring | Probe configured HTTPS/WSS routes and metrics bearer/loopback gates from allowed and denied QA network segments. Local Docker HTTP hops and actual firewall exposure require BQ-019 approval/VM evidence. | `DEP-06`, `OBS-02`, `SEC-02`; `scripts/bundle/assemble-runtime-bundle.sh` |
| Webhook Test and integrations | Confirm only authorized managers can configure keys/SSO/webhooks, one-time secrets do not reappear, and explicit Test delivery cannot target prohibited destinations. Automatic delivery and login integration are outside release scope. | `FUN-12`, `API-04`; integration routes |
| Cache and privacy | Verify two-minute lock removes cached media and stops emergencies while preserving identity and already-spooled PoP. Inspect permissions and stale content after purge/reconnect; do not infer secure overwrite. | `PLAYER-03..04`, `PLAYER-07`; player security/cache code |

Security cases are planned assessments, not penetration-test results. Record evidence of both allowed and denied actors. BQ-007 is resolved for the four content-resource ownership rules but not OPERATOR-directory privacy; BQ-020 is resolved for account tombstones but not Media/chat recycle behavior. BQ-015/019 and those remaining subtopics still require human acceptance.
