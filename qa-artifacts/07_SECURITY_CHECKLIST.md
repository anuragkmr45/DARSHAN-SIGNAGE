# Security Verification Plan

Planning only. Perform the following checks only in an approved isolated environment with nonproduction accounts, objects and keys. Map findings to `03_RISK_REGISTER.csv` and case IDs in `05_TEST_CASES.csv`. OWASP ASVS/WSTG categories are organizing references, not a claim of certification.

| Control area | Human verification | Case IDs / evidence |
| --- | --- | --- |
| Identity and sessions | Test wrong/inactive/deleted credentials, expiry/logout and immediate withdrawal from REST and already-connected sockets. After disable/delete, password, role, department and direct/transitive permission changes verify JTIs disappear transactionally, every API node disconnects local rooms, protected socket actions revalidate, and reconnect is rejected. Test already-running work and recovery CLI separately. | `AUTHN-01..04`, `CONC-07`; auth verifier, user/role repositories, session invalidation, socket-session and realtime bus |
| Role administration | Test last-active SUPER_ADMIN delete/disable/demotion, two-account and concurrent cases plus recovery CLI. Verify custom roles authorize by effective permission/inheritance/condition regardless of name and cannot bypass protected system-role hierarchy. | `AUTHZ-01..02`; super-admin invariant, RBAC resolver, role routes |
| Directory privacy | Probe users/operators/invites/chat participant lists, totals, search, pagination and guessed detail/member IDs. Non-global actors see only active non-deleted self/same-department people; global User managers may see all. | `AUTHZ-08`, `SEC-01`; user-directory helper, user repository and chat/conversation routes |
| Horizontal authorization and ownership | Use organization, two departments and restricted rows with creator, peer, moved/deleted creator, custom roles and global managers. Media/Layout permit same-department read but creator/global mutation; Presentation adds nested closure with the same mutation rule; Schedule permits action-specific same-department management. Cross-department and restricted access is denied. | `AUTHZ-09..13`, `SEC-01`; content ownership helper and content routes |
| Tombstone privacy and integrity | Confirm normal directories/search/invites omit deleted users; history exposes retained name/status but never the original email/password/invite token; original email is reusable; second delete is idempotent; update/reactivate/login/reset/activation fail. Confirm creator/owner columns and historical Schedule Request/audit/chat references are unchanged. | `DATA-06`, `UI-07`; migration `0045`, user repository/routes, audit/request projections |
| Delegated emergency | Test CMS and direct API trigger/status/history/clear with conditional Screen records. A delegate succeeds only for an all-authorized direct-screen set; group/global/mixed/out-of-scope is denied. A global Emergency manager may use all scopes. Revoke permission mid-operation and validate READY/readable Media. | `AUTHZ-03`, `FUN-07`; emergency authorization helper and route |
| Disabled Requests exposure | Confirm every former general `/requests` method/path, CMS route, client, report and webhook surface is absent/not-found even with legacy rows. Confirm `/schedule-requests` remains functional. | `AUTHZ-06`, `SEC-01`; requests-disabled contract |
| Browser session and CSRF | Inspect same-site cookies, credentialed requests, origin/CSRF checks, direct URL access, stale tabs and error responses. Verify that hiding a CMS control does not stand in for a backend denial. | `AUTHN-02`, `UI-02`, `SEC-01`; `darshan-cms/src/api/apiClient.ts`, `darshan-server/src/server/index.ts` |
| Inputs and output encoding | Use benign malformed inputs for IDs, Unicode, template text, markdown/chat messages and exported PDF/CSV; confirm validation and encoded rendering. Check database writes and logs for accidental partial or secret data. | `API-01`, `FUN-09`, `FUN-11`; server schemas/routes and `src/utils/pdf-render.ts` |
| Document page selection | Reject API over-posting, zero/negative/fractional/overflow pages, page values on non-documents, invalid layout slots and non-READY media before replacement. Confirm a refreshed count never silently rewrites an invalid restored selection. For an isolated post-publish mismatch, require exact `Unavailable`, safe `DOCUMENT_PAGE_OUT_OF_RANGE` context and no request/render of an alternate page. Confirm signed PDF access remains authorized/short-lived, PDFs are parsed without script evaluation, and errors/logs expose neither source bytes nor signed URLs. | `FILE-06`, `UI-05`, `API-05`, `API-06`, `PLAYER-10`, `SEC-01`; PDF metadata/selection, CMS hydration and player PDF renderer |
| Video failure, retry and teardown | Over-post loop on non-video media and verify normalization. Interrupt load, seek, play retry, stall, fade and normal playback using schedule end, snapshot replacement, emergency/default takeover and secure lock. A multi-item failure must retain `Unavailable` only to its original boundary; a one-item failure may hold one 1–30 second retry timer. Confirm every hidden video is paused, detached and stripped of its source; no hidden audio, stale callback, retry storm, signed media URL or credential remains. | `API-07`, `PLAYER-11..15`, `OBS-04`; scheduled-video lifecycle, player layout helpers and renderer |
| Uploads and object access | Check MIME, size, SHA-256, multipart ownership, signed URL expiry, wrong/deleted user/session, object-key traversal and private download access. Race deletion against INITIALIZING/ACTIVE/FINALIZING and legacy PENDING uploads in both commit orders; inject abort/delete failure and prove no incomplete object becomes READY while cleanup retries safely. | `FILE-01..05`, `CONC-02`, `CONC-07`; media/user/upload repositories, `darshan-server/src/routes/media.ts`, `src/jobs/index.ts`, `src/s3/index.ts` |
| Webpage transport, authentication and SSRF boundary | Test policy-disabled/enabled HTTP, HTTPS trust, URL username/password, HTTP-auth challenge, nonpersistent player partition, host/resource allowlists, every redirect/navigation hop, final URL, DNS rebinding, allowed private CIDR and hard-denied loopback/link-local. Confirm enabled HTTP is documented as cleartext and never use a real internal target or credential. | `FUN-08`, `PLAYER-09`, `WEB-01..03`; server/player webpage policy and capture/view managers; BR-097..099 |
| Webpage preview integrity | Tamper with object bytes/checksum/revision, fail capture/object upload/DB publication in turn, and race refresh with deletion. The last committed successful preview remains usable, a stale worker cannot publish, corrupt/missing bytes show a controlled unavailable state, and logs/responses reveal no signed URL or internal destination. | `WEB-04..06`, `REL-02`; migration `0047`, webpage jobs/serializers, player revision cache; BR-100 |
| Device identity and replay | Test certificate/site mismatch, revoked identity, timestamp/nonce replay, signed REST versus socket handshake, and resumption after network failure. TLS transport trust and signed request authorization are separate checks. | `API-02`, `PLAYER-01`; server device auth and player cert manager |
| Secrets and release trust | Verify target host has independently pinned public key, signed manifest covers installer and role, unsafe archives reject before activation, runtime secrets stay outside browser bundle/logs and are readable only by intended process. | `DEP-01`, `SEC-02`; `scripts/bundle/install-signed-role.sh`, role lifecycle |
| Network and monitoring | Probe configured HTTPS/WSS routes and metrics bearer/loopback gates from allowed and denied QA network segments. Local Docker HTTP hops and actual firewall exposure require BQ-019 approval/VM evidence. | `DEP-06`, `OBS-02`, `SEC-02`; `scripts/bundle/assemble-runtime-bundle.sh` |
| Webhook Test and integrations | Confirm only authorized managers can configure keys/SSO/webhooks, one-time secrets do not reappear, and explicit Test delivery cannot target prohibited destinations. Automatic delivery and login integration are outside release scope. | `FUN-12`, `API-04`; integration routes |
| Cache, identity and locked recovery | Verify the exact 120-second authenticated-success deadline stops schedule/default/emergency and removes only media-cache targets while preserving identity, certificates, logs, PoP and request queues. Reachability while locked may start one recovery but cannot unlock directly. Require identity validation and a forced fresh snapshot before current-content sync/authority apply; revoked/mismatched identity returns to pairing and stale cached authority never resumes. Inspect permissions and stale content after purge/reconnect; do not infer secure overwrite. | `PLAYER-03..04`, `PLAYER-07`, `PLAYER-16`; heartbeat, secure guard, PlayerFlow, snapshot manager and media-cache purge |

Security cases are planned assessments, not penetration-test results. Record evidence of both allowed and denied actors. The content-resource and people-directory boundaries are now explicit release requirements; BQ-020 Media/chat recycle behavior and BQ-015/019 site-policy inputs still require human acceptance.
