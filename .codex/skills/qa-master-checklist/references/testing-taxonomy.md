# Testing Taxonomy Reference

Use these categories to avoid missing important dimensions while keeping the final package repository-specific.

## Product/business
- personas and roles
- use cases/user journeys
- business rules
- calculations
- state transitions
- approvals/escalations
- ownership/tenant rules
- quotas/limits
- time/date rules
- notifications
- cancellation/reversal

## Functional/technical
- UI
- API/contract
- validation
- database/data integrity
- search/filter/sort/pagination
- files/storage
- background jobs
- webhooks/events
- integrations
- caching
- concurrency/idempotency

## Non-functional
- security
- performance
- scalability/capacity
- reliability
- resilience
- recoverability
- accessibility
- compatibility
- observability
- maintainability/operability evidence where testable

## Delivery/operations
- configuration
- deployment
- migration
- rollback
- feature flags
- backup/restore
- disaster recovery
- smoke/regression/UAT
- release readiness
